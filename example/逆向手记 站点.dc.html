从一个 sign 参数入手：还原某电商平台商品详情接口的签名算法

商品详情接口带一个 32 位的 sign，改动任意查询参数都会返回 403。整个过程分三步：定位生成位置、剥离混淆、脱离浏览器环境复现。以下按实际调试顺序记录。

封面占位
1600 × 800

一、请求长什么样

抓包结果里除业务参数外多了 t、nonce、sign 三个字段。t 是毫秒时间戳，nonce 每次刷新都变，sign 长度固定 32 位，大概率是 MD5，但盐值与拼接顺序需要确认。

REQUEST
GET /api/v2/item?id=1024
  &t=1755772800123
  &nonce=8f2c1a
  &sign=c41d8f...9e2b
RESPONSE · 改动一个字符后
HTTP/1.1 403
{
  "code": 40301,
  "msg": "invalid signature"
}

二、调用链

XHR 断点打上后向回翻三层堆栈，落点在打包后的请求拦截器。整条链路如下，方括号内为压缩后的函数名。

{{ n.i }} {{ n.fn }} {{ n.note }}
✓ sign 写回 query，请求放行

直接搜 sign 会有数十处命中，从 CryptoJS.MD5 反向定位更快。

HOOK.JS 粘贴到控制台 
// 拦截所有走这个方法的调用，命中即断下
const _md5 = window.CryptoJS?.MD5;
window.CryptoJS.MD5 = function (msg) {
  console.log('[md5 in]', msg.toString());
  debugger;
  return _md5.apply(this, arguments);
};

命中后控制台打印的明文串即为拼接结果，顺序一目了然。

三、脱环境复现

明文格式确认为 key=value 按字典序拼接，尾部追加一段硬编码盐。剩下的部分用 Python 几行即可复刻，不需要挂 Node 环境。

SIGN.PY
import hashlib, time, random

SALT = "a3f9...c7"

def make_sign(params: dict) -> str:
    params["t"] = int(time.time() * 1000)
    params["nonce"] = f"{random.getrandbits(24):06x}"
    raw = "&".join(f"{k}={params[k]}" for k in sorted(params))
    return hashlib.md5((raw + SALT).encode()).hexdigest()

盐值会随版本变动。上线的采集脚本不建议写死，保留一条从最新静态资源中提取的兜底逻辑，长期维护成本更低。
